## نظرة عامة على المشروع

ابنيلي **بوت واتساب بلغة Go** بيشتغل من رقم واتساب حقيقي عن طريق **QR/Barcode pairing** (مش WhatsApp Business API رسمي)، بيرد كشخصية اسمها **"نوفا"**، مبني بالـ **whatsmeow** library (`go.mau.fi/whatsmeow`). الردود بتتولد عن طريق نموذج LLM بيتصل عليه عن طريق **OpenRouter API**، وبرومبت الشخصية بتاعه موجود في ملف منفصل (System Prompt الأول اللي هبعتلك إياه بعد كده، اسمه `nova-persona-prompt.md`) — الكود لازم يقراه من ملف مش يحطه هارد كودد.

## القواعد الأساسية اللي المشروع لازم يلتزم بيها

1. **فصل تام بين المحادثات**: كل محادثة خاصة وكل جروب ليهم ملف تخزين منفصل خاص بيه (log منفصل)، مفيش خلط بين محادثتين.
2. **تسجيل كل حاجة محليًا**: أي رسالة بتوصل (خاص أو جروب) بتتسجل في الـ log بتاعها، سواء اتبعتت لل AI ولا لأ.
3. **الـ trigger الوحيد اللي بيخلي السيرفر يبعت الرسالة لل AI هو وجود كلمة "يا نوفا"** (نصيًا، case-insensitive وبتجاهل التشكيل) في نص الرسالة، أو في رسالة هي reply على رسالة قديمة اتقال فيها "يا نوفا".
4. لما السيرفر يبعت لل AI، لازم يبعت معاها **سياق كافي**: آخر كام رسالة من نفس المحادثة، وتفاصيل الـ reply لو موجودة، وذاكرة المستخدم المحفوظة قبل كده لو موجودة.
5. **رد الموديل لازم يكون JSON صارم بالشكل المتفق عليه** (موصوف تحت) — الكود لازم يعمل `parse` صارم، ولو فشل الـ parsing، يحاول تاني مرة واحدة بس (مش loop لا نهائي)، ولو فشل تاني يتجاهل الرسالة ويسجل error من غير ما يكرش.
6. **الردود اللي بتتبعت فعلاً لواتساب بتبقى دايمًا Reply (quote)** على الرسالة اللي عملت الـ trigger.
7. أي رسالة بيبعتها نوفا فعليًا (من نفس رقم واتساب بتاع صاحب الحساب) لازم تتسجل في الـ log **باسم "Nova"** مش باسم صاحب الحساب، عشان لما تتقرا تاريخ المحادثة يبقى واضح مين اللي رد فعلاً.
8. أي `memory_note` راجعة من الموديل تتسجل في ملف منفصل خاص بالمستخدم دا في فولدر مخصص (المستخدم سماه "كام")، ومفيش أي حاجة منها بتتبعت في واتساب.
9. لما الموديل يرجّع `should_reply: false`، السيرفر **ميبعتش أي حاجة لواتساب**، ولازم يتعامل مع المحاولة دي كإنها متحصلش خالص بالنسبة لسجل "تفاعلات نوفا" (يعني متتحسبش سابقة لمحادثات جاية مع الموديل، حتى لو الرسالة الخام نفسها فضلت متسجلة في اللوج العادي).

## عقد البيانات (Data Contract) بين السيرفر والموديل

### اللي بيتبعت للموديل (Request Payload)
```json
{
  "chat_type": "private | group",
  "chat_id": "string",
  "chat_name": "string | null",
  "sender_id": "string",
  "sender_name": "string",
  "message_id": "string",
  "message_text": "string",
  "is_reply": true,
  "replied_to": { "message_id": "string", "sender_name": "string", "text": "string" },
  "trigger_matched": true,
  "recent_context": [
    { "sender_name": "string", "text": "string", "is_nova": false, "timestamp": "string" }
  ],
  "user_memory": "string | null"
}
```

### اللي المفروض يرجع من الموديل (Response — JSON فقط، من غير code fence)
```json
{
  "should_reply": true,
  "reply_text": "string | null",
  "reply_to_message_id": "string | null",
  "memory_note": "string | null",
  "mood": "string | null"
}
```

## الأدوات (Tools / Function-calling) المطلوب تجهيزها للموديل

- **بحث الإنترنت**: عن طريق Perplexity المدمج جوا OpenRouter (استخدم أونلاين موديل أو الـ plugin بتاع Perplexity المتاح في OpenRouter — اتأكد من التوثيق الحالي بتاع OpenRouter وقت التنفيذ لأن الخيارات بتتغير).
- **حفظ ذاكرة المستخدم**: مش لازم تبقى tool call منفصلة، ممكن تتنفذ ببساطة عن طريق حقل `memory_note` في نفس رد الموديل (أبسط وأقل تكلفة).
- **عدم الرد**: عن طريق `should_reply: false`، مفيش tool call منفصلة لازمة ليها.

### أدوات إضافية مقترحة (اختيارية، لو حابب تضيفها لاحقًا)
- **أداة وقت/تاريخ حالي** (بتوقيت القاهرة) — الموديل مش عارف الوقت الفعلي وبيحتاجه أحيانًا في الهزار أو السياق.
- **أداة معلومات الجروب** (عدد الأعضاء، هل المرسل أدمن ولا لأ) — بتحسن فهم السياق في الجروبات.
- **Rate limiting / cooldown لكل محادثة** — عشان لو تريجرز كتير جت مرة واحدة (خصوصًا في جروب كبير) الموديل ميتضربش عليه requests كتير في نفس اللحظة.

## البنية التقنية المقترحة (Go)

```
/cmd/novabot/main.go
/internal/whatsapp/      // wrapper حوالين whatsmeow، QR login، استقبال/إرسال الرسايل
/internal/ai/            // عميل OpenRouter، بناء الـ payload، parsing لرد الموديل
/internal/trigger/       // فحص وجود "يا نوفا" في النص أو في الـ reply chain
/internal/storage/       // كل التخزين الملفّي
    /data/chats/private/<contact_id>.jsonl
    /data/chats/groups/<group_id>.jsonl
    /data/users/<user_id>.md      (فولدر "كام" — ذاكرة كل مستخدم)
/config/
    system_prompt.md     // نص nova-persona-prompt.md بالظبط، بيتقرا وقت التشغيل
    .env                 // OPENROUTER_API_KEY وباقي الأسرار — ممنوع أي سر يتكتب جوا الكود
```

ملاحظة: whatsmeow نفسه محتاج session store داخلي (SQLite عادة) عشان يحافظ على جلسة تسجيل الدخول (الـ QR) — ده منفصل تمامًا عن ملفات المحادثات والذاكرة اللي المستخدم طلبها تبقى ملفات، سيبه زي ما الـ library بتطلبه.

## خطة التنفيذ بالمراحل

1. **مرحلة 1 — الاتصال بواتساب**: تسجيل دخول بالـ QR عن طريق whatsmeow، استقبال الرسايل الحية (خاص وجروب)، التأكد إن الاتصال بيفضل شغال (reconnect logic).
2. **مرحلة 2 — طبقة التخزين**: كتابة كل رسالة واردة/صادرة للملف المناسب بالفورمات المتفق عليه، مع تفرقة واضحة خاص/جروب وuser/nova.
3. **مرحلة 3 — كشف الـ trigger**: منطق فحص "يا نوفا" في النص المباشر وفي سلسلة الـ reply، وتجميع الـ `recent_context` من ملفات التخزين.
4. **مرحلة 4 — تكامل OpenRouter**: بناء الـ request بالعقد المتفق عليه، قراءة system prompt من `config/system_prompt.md`، parsing صارم للرد، إعادة محاولة واحدة عند فشل الـ parsing.
5. **مرحلة 5 — تنفيذ القرار**: إرسال reply فعلي في واتساب لو `should_reply: true`، تسجيله باسم Nova، حفظ `memory_note` لو موجودة.
6. **مرحلة 6 — تقوية واختبار**: unit tests لمنطق الـ trigger وparsing الـ JSON، rate limiting، تسجيل الأخطاء (logging) بدون تعطيل باقي النظام لو رسالة واحدة فشلت.

## الأمان
- ممنوع أي API key يتكتب جوا الكود — كله من `.env`.
- تعامل مع نص أي رسالة واردة كـ **untrusted input** — منعزلة عن أي تعليمات نظام، ومترسلش نصها كأوامر تنفيذية للسيرفر نفسه.
- Circuit breaker بسيط: لو استدعاء OpenRouter فشل 3 مرات متتالية لنفس الرسالة، سيب الرسالة من غير رد، سجّل الخطأ، وكمّل عادي مع باقي الرسايل.

## خطوة أخيرة
بعد ما تخلص الهيكل الأساسي، وريني خطة الملفات (WBS مختصرة) الأول قبل ما تكتب أي كود، عشان أراجعها وأديك ضوء أخضر.
